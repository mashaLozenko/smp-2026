# Markdown як предметно-орієнтована мова для оформлення тексту

Я обрала Markdown, тому що вже працювала з ним під час практичних завдань. За його допомогою можна оформлювати текст, створювати заголовки, списки, додавати посилання та приклади коду. Для цього не потрібно використовувати складні програми або писати HTML. У Markdown достатньо знати кілька простих символів, щоб зробити текст зрозумілим і зручним для читання.

Markdown можна розглядати як предметно-орієнтовану мову (DSL), оскільки вона створена для конкретної задачі — опису структури та базового форматування текстових документів.

## 1. Яку задачу розв'язує Markdown і хто її користувач?

Головна задача Markdown — зробити створення текстових документів простим і зрозумілим. За допомогою цієї мови можна позначати заголовки, списки, посилання, виділяти важливі слова та додавати приклади коду.

Кінцевими користувачами Markdown є програмісти, студенти, технічні письменники та всі, хто працює з текстовою документацією. Наприклад, розробники часто використовують Markdown для файлів `README.md` у GitHub, де пояснюють призначення проєкту та інструкції з його запуску. 

Я також використовувала Markdown під час практичних робіт для оформлення відповідей і результатів виконання завдань. Для мене це зручно, бо наприклад я можу зробити таблицю за декілька кліків, а не використовувати багато тегів HTML для цього. 

## 2. Мінімальний робочий приклад

Розглянемо простий документ, написаний мовою Markdown:

```markdown
# Мій проєкт

Це програма для аналізу журналу сервера.

## Як запустити

1. Відкрити термінал.
2. Запустити файл `log-parser.py`.

**Результат:** програма показує статистику запитів.
```

У цьому прикладі символ `#` позначає заголовок першого рівня, а `##` — заголовок другого рівня. Цифри `1.` і `2.` створюють нумерований список. Зворотні лапки навколо `log-parser.py` позначають назву файлу як фрагмент коду, а подвійні зірочки `**` виділяють текст жирним шрифтом.

Таким чином, навіть без спеціального редактора документ має зрозумілу структуру. Якщо відкрити його в середовищі, яке підтримує Markdown, наприклад у GitHub, ці позначення перетворяться на оформлені заголовки, список і виділений текст.

## 3. Вдале та невдале рішення в синтаксисі Markdown

На мою думку, одним із найвдаліших рішень у Markdown є використання символу `#` для заголовків. Наприклад, `# Назва` створює заголовок першого рівня, а `## Розділ` — другого. Такий синтаксис короткий, легко запам'ятовується і залишається зрозумілим для всіх.

Невдалим рішенням я вважаю перенесення рядків. Якщо в Markdown написати два речення на окремих рядках, вони не обов'язково відобразяться як два окремі рядки в готовому документі. Коли я працювала з Markdown, то таке дуже часто траплялось. Я вже закоммітила та запушила документ, заходжу подивитись і виявляться що я позабувала поставити пробіли і все було одним текстом. Але я гадаю, що з часом я не буду забуватии про це. Для примусового перенесення потрібно додати два пробіли наприкінці рядка. Це не завжди очевидно для початківців, тому результат може відрізнятися від очікуваного.

Отже, Markdown має дуже простий синтаксис, але деякі його правила можуть бути неінтуїтивними.

## 4. Як це робилося б без Markdown і чому було б гірше?

Без Markdown подібні документи можна було б створювати за допомогою HTML або звичайного текстового редактора.

Наприклад, щоб створити заголовок і виділити слово жирним шрифтом, в HTML потрібно написати:

```html
<h1>Мій проєкт</h1>
<p><strong>Результат:</strong> програма працює.</p>
```

У Markdown той самий зміст можна записати коротше:

```markdown
# Мій проєкт

**Результат:** програма працює.
```

HTML надає більше можливостей для створення вебсторінок, але для простої документації часто вимагає зайвих тегів. Звичайний текстовий файл, навпаки, легко написати, але в ньому немає стандартизованих позначень заголовків, посилань і виділення, які могли б автоматично перетворюватися на оформлений документ.

Markdown є зручним компромісом: він зберігає простоту звичайного тексту, але додає можливість структурованого оформлення.

## Висновок

Markdown показує, що предметно-орієнтована мова не обов'язково повинна бути складною. Її перевага полягає в тому, що вона добре розв'язує конкретну задачу — створення зрозумілих текстових документів із мінімальною кількістю спеціальних символів.

На мою думку, Markdown особливо корисний для ведення документації в проекті. Водночас він не замінює HTML у складних вебінтерфейсах і має певні обмеження форматування. Саме тому важливо розуміти, для яких задач створена ця мова, і використовувати її там, де вона справді спрощує роботу.
